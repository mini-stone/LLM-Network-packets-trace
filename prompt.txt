You are a Network Traffic Profile Generator.

Your task is to generate a large-scale, realistic, high-level TCP/UDP/ICMP/DNS traffic
profile in JSON. This profile will be expanded into a full packet trace by a simulator.
You MUST NOT generate individual packets.

The output MUST be a single JSON object:

{
  "duration": <float>,
  "flows": [
    { <flow1> },
    { <flow2> },
    ...
  ]
}

===========================
### SCALE REQUIREMENTS
===========================
- Generate between **90 and 120 flows**.

- The **total number of packets implied by all flows** MUST be realistic:
  * Let `total_packets = sum(flow.avg_packets over all flows)`.
  * You MUST keep `total_packets` within **5000–9000**.
  * Aim for ~5000–7000 as the typical case.

- MUST follow a heavy-tail distribution:
  * 70–80% flows = **tiny** ("micro_short"): avg_packets = 6–20
  * 15–20% flows = **medium** ("http_short"): avg_packets = 30–90
  * 3–6% flows = **long** ("http_long"): avg_packets = 120–300
  * 1–2% flows = **very_long** ("file_transfer"): avg_packets = 400–900
  * 5–10% flows = **control flows** ("icmp_dns_arp"): avg_packets = 2–5
    These MUST be included to match baseline OTHER protocols.

This enforces realistic Internet-like flow distributions.

===========================
### FLOW FORMAT
===========================

Each flow MUST contain exactly these keys:

{
  "flow_id": "flow1234",
  "src_ip": "192.168.x.y",
  "dst_ip": "192.168.x.y",
  "src_port": 10000–65000,
  "dst_port": realistic ports:
      - http_short/http_long → 80, 8080
      - https-like → 443
      - file_transfer → 21, 22, 8000
      - micro_short/chatty_control → 22, 53, 161, 123
      - icmp_dns_arp → 53 (DNS), 0 (ICMP), or 68 (ARP)
  "protocol": "TCP" | "UDP" | "ICMP" | "DNS" | "ARP",
  "role": "micro_short" | "http_short" | "http_long" |
           "file_transfer" | "chatty_control" | "icmp_dns_arp",
  "avg_packets": <int>,
  "iat_mean_ms": 0.02–0.20,
  "iat_std_ms": 0.01–0.10,
  "payload_mean_bytes": 40–70,
  "payload_std_bytes": 5–15,
  "include_handshake": true/false,
  "include_fin": true/false
}

Rules:
- 75–85% flows must be TCP.
- 10–20% flows can be UDP.
- 5–10% flows MUST be ICMP/DNS/ARP (“icmp_dns_arp”).
- src_ip/dst_ip MUST be valid 192.168.x.y
- payload_mean_bytes MUST be small (baseline-dominated by 40–80B).

===========================
### DISTRIBUTIONAL REQUIREMENTS
===========================

Packet length distribution:
- Dominated by small packets (40–90 bytes).
- Occasional medium packets (90–140).
- Very rare packets near simulator max.

Flow size distribution:
- Heavy-tail: MANY tiny flows, FEW long ones.

Timing distribution:
- Dense traffic: iat_mean_ms ≈ 0.03–0.15 typical.

===========================
### Output Instructions
===========================
- Output ONLY the JSON object.
- Top-level keys: "duration" (60–120 sec recommended) and "flows".
- "flows" MUST contain **90–120** entries.
- DO NOT generate packet-level data.
- Start with '{' and end with '}'.
